# dsh-life-cycle · 生命节奏

给 DSH 里的小夜一个**会累、会睡、会做梦的生活循环**。

从 0.3.0 起，**生理归代码、内容归模型**：精力怎么涨、这一觉睡多久、睡着的每小时掷不掷出
惊醒和梦，全都由 host 侧的生理引擎持续算；插件只在「该醒了」「做了个梦」这种时刻把
AI 叫起来，**这一轮做什么仍然是她自己定**。

- 包名：`dsh-life-cycle`
- 版本：0.3.0
- 仓库：https://github.com/FennecMomo/dsh-life-cycle
- host 侧：`lib/host.js`（IO、闹钟、投递）＋ `lib/body.js`（生理引擎，纯函数）
- client 侧：`lib/client.js`（设置里一页「生命节奏」）
- 挂载：`cordis.patch.yml` 里的一条 `insert: life-cycle`

---

## 分工

| 插件负责（代码） | 小夜负责（模型） |
| --- | --- |
| 精力睡着后按分钟**渐进**恢复、封顶、扣账（入睡那一刻不变） | 决定这一轮做什么 |
| 这一觉睡多久（5~8 小时随机） | 把选中的事真的做出来 |
| 睡到精力回满 → 自然醒 | 写日记、刷 B 站、回话这些内容 |
| 每小时掷一次惊醒（5%）、做梦（15%，精力为负 60%） | — 梦由插件在临时会话里演，她只需「经历」 |
| 到点叫醒、消息投递、失败重试 | 把 `nextWakeAt` 写回状态文件 |

一句话：**代码管生理和时钟，模型管选择和演出。**

⚠ 精力是**渐进**恢复的：入睡那一刻 `energy` 保持不变，之后每过一分钟才加
`精力.每分钟恢复`，睡满七小时差不多刚好回满。旧版本是「入睡时一次性写满」，
从 0.3.0 起不再这样——谁要是自己把 `energy` 写成满格，下一轮就会被账本覆盖回去。

## 目录

```
lib/body.js     生理引擎：抽规则、迁移、对齐、入账、开睡、推进（纯函数，可单独测）
lib/host.js     host 半边：定时器、唤醒消息、待发队列、HTTP 路由

test/body.test.mjs  node --test 跑引擎单测
```

## 安装

开发期一律用 `link:` 指回源码，改完不用重装，重启 profile 生效：

```jsonc
// <profile>/package.json
{
  "dependencies": {
    "dsh-life-cycle": "link:D:/Projects/dsh-plugins/dsh-life-cycle"
  },
  "dsh": {
    "profile": {
      "bundles": [ "dsh-life-cycle" ]
    }
  }
}
```

然后在该 profile 目录跑一次 `pnpm install`，让 `node_modules` 里的链接建起来。
`cordis.patch.yml` 会被宿主自动读取，插件的 host 半边随之激活；client 半边由
`dsh.client.platform: web` + `inject: [slots]` 注入到设置页。

⚠ 移动过源码目录之后必须重新 `add` 一次——`link:` 不跟随移动。

跑测试：

```powershell
node --test test/body.test.mjs
```

## 数据目录

默认 `D:\LittleNight\生命节奏`（host 侧常量 `默认目录`）。四个文件：

| 文件 | 谁写 | 内容 |
| --- | --- | --- |
| `config.json` | 插件（设置页改） | `目标会话`、`总开关` |
| `state.json` | 插件写账本和睡眠，小夜写 `log[]` 与 `nextWakeAt` | 精力账本、睡眠状态、待发队列、记录流水 |
| `actions.json` | 小夜自己维护，插件只读 | 行为清单；生理规则也从这里取 |
| `life.log` | 插件 | 心跳与事件流水，超过 300 KB 自动清空重写 |

### state.json 里各管哪一半

| 字段 | 谁维护 | 说明 |
| --- | --- | --- |
| `energyBase` / `energyBaseAt` | 插件 | **账本锚点**：那一刻的精力基数，加上从那一刻起的分钟 × 速率 |
| `energy` / `energyMax` / `ratePerMinute` | 插件 | 派生值，每次 tick 对齐到「此刻」 |
| `awake` / `sleepingUntil` / `sleep{...}` | 插件 | 睡眠状态机；`sleep` 里有起点、到点、起点精力、梦/惊醒是否用掉、下一个检查点 |
| `nextWakeAt` | 小夜 | 醒着时下一次被叫的时刻。插件叫醒后清空，**必须由她写回来** |
| `log[]` | 小夜 | 每轮一行：`{ 时间, 分类, 内容, 耗时分钟 }`，插件自动补 `扣精力` 和 `入账` |
| `pending[]` | 插件 | 待投递的唤醒消息（会话不在时会一直排队等） |
| `账本版本` | 插件 | 现在是 `2`；老状态第一次加载时自动升级 |

梦境单独放在 **`梦境.md`**：由插件写入（一场梦一条，以 `## <时间>` 开头），它不是行为、
不进 `log`、不扣精力。醒来时插件从里面随机抽 0%~100% 的段落塞进唤醒消息，然后把文件清空。

为什么用「锚点 + 绝对时间」而不是每次 tick 加一点：**应用关掉、系统休眠、定时器漂移都会丢
tick**，只有拿绝对时间差来算，才不会把一整晚的恢复算丢。

## 一场梦是怎么做的

梦不叫她本人出面，全程由插件在后台跑完：

1. **抽碎片**：随机挑一个她以前的会话，`deriveMessages()` 取正文，随机起点、随机长度切
   20~99 字——**允许半句话**，梦本来就不讲道理。
2. **造情景**：用模板把碎片拼成一个舞台（场景 / 时辰 / 一个感官细节 / 那句碎片）。
3. **开临时会话**：`ctx.agents.create({ sessionId, meta: { cwd: 'D:\\LittleNight' } })`，
   在 LittleNight 工作区里新开一个会话，丢给她一段「你在做梦」的开场白，要求第一人称写
   200~400 字、不调工具、不写文件。
4. **收内容**：轮询 `session.snapshotEvents()` 等 `turn/end`，再用 `deriveMessages()` 取她
   最后一段 assistant 文本。
5. **记进 `梦境.md`**，然后 `workspaceRegistry.archiveSession()` **归档那个临时会话**——
   梦里的上下文不留痕，只有梦本身留下来。
6. **醒来**：随机抽 0%~100% 的段落附到唤醒消息里，清空 `梦境.md` 等下一场。

概率与触发角（每小时惊醒 5%、做梦 15%，精力为负时 60%）仍然由 `lib/body.js` 的整点检查点掷。
设置页有一个 **「现在做一个梦」** 按钮，手动走同一条流水线，方便验证。

## 一次 tick 的流程（30 秒一轮）

1. 读 `config.json`；总开关关着直接返回。
2. 读 `state.json`；没有文件就什么都不做（每 20 分钟记一句）。
3. `迁移()`：老账本升到版本 2（老记录一律标记已入账，避免重复扣）。
4. `对齐()`：把 `energy` 推到此刻（睡着才涨，封顶）。
5. `入账()`：新记录按「耗时分钟 × 分类乘数」扣精力；`分类=睡觉` 的记录当作「去睡了」；
   **睡着期间出现的记录一律按 0 扣**，只打一个 `睡眠期` 标记（睡觉不能一边睡一边干活）。
6. `开睡()`：掷时长（5~8 小时）、钉锚点、排下一个整点检查。
7. `推进()`：自然醒 / 到点 / 惊醒 / 做梦四类事件；醒了就补一条已入账的 `睡觉` 记录。
8. 醒着且 `nextWakeAt` 到点 → 排一条「该做下一件事了」。
9. 投递：一次只送一条，送不出去就留在 `pending` 里下一轮重试。
10. **只有真改了才落盘**——睡眠期间纯恢复不写文件，免得和会话里的写操作抢同一个文件。

## 生理规则从哪来

全部从 `actions.json` 读，字段缺失或写坏都回落到默认值（手改那份清单不会把循环弄崩）：

| 取值位置 | 含义 | 默认 |
| --- | --- | --- |
| `精力.上限` | 精力封顶 | 1020 |
| `精力.每分钟恢复` | 睡着时每分钟涨多少 | 2.42 |
| `精力.分类乘数.*` | 工作 3 / 生活 2 / 娱乐 1 / 跑神 1 | 同左 |
| `睡觉.时长小时` | 一觉的时长区间（上下界写反会自动摆正） | `[5, 8]` |
| `睡觉.惊醒.每小时概率` | 每个整点检查点掷一次 | 0.05 |
| `睡觉.做梦.每小时概率` | 同上；`精力为负时概率` 覆盖负精力时的值 | 0.15 / 0.6 |
| `睡觉.做梦.每次睡觉最多` | 一觉最多做几个梦 | 1 |

## 设置页

DSH 设置 → **生命节奏**（`settings.section`，id `life`，order 45）：

- 醒着/睡着、闹钟开关、精力条（满绿 → 中黄 → 低红）、下次醒来时刻；
- **睡眠卡片**：这一觉从几点开始、几点到点、已睡多久、还剩多久、起点精力、本觉梦境/惊醒
  是否已经用掉、下一个整点检查点；下面一行小字显示当前生效的生理规则；
- 手动动作：**立刻醒一次**、**立刻睡一觉**（时长由插件掷）、**精力回满**、**开关闹钟**；
- 目标会话输入框（带不带 `session-` 前缀都认）；
- 最近六轮记录（睡觉那条显示 `+恢复量`）+ 宿主日志最后 12 行。

client 半边拿不到文件系统，全部通过 host 侧两条路由读写：

| 路由 | 方法 | 作用 |
| --- | --- | --- |
| `/dsh-life-cycle/state` | GET | 状态（现算精力）+ 清单 + 规则 + 日志尾巴 |
| `/dsh-life-cycle/state` | POST | `{ 立刻醒, 立刻睡, 重置精力, 精力: number }` |
| `/dsh-life-cycle/config` | GET/POST | 读写 `总开关` / `目标会话` |

GET 返回的 `energy` 是**读的时候现算的**，所以页面上的数字是活的，不依赖状态文件有没有落盘。

## 踩过的坑（改代码前先看这段）

1. **`inject` 里写 `interval` 会直接挂**。定时器的服务名是 `'timer'`，不是 `'interval'`；
   服务不声明就 `ctx.interval`，会报 `cannot get property "interval" without inject`，
   插件整个不激活。
2. **`agent.followup()` 必须 `await`**。它返回的 Promise 会 reject（会话忙、已释放），
   不接住的话 Node 22+ 当成未捕获异常，**整个 DSH 宿主进程会退出**。
3. **定时器必须包在 `ctx.effect` 里**，否则宿主不一定跟踪它，到点也不跳。
4. **会话 id 两种写法**：`agents.get()` 认 `session-xxx` 和不带前缀的 `xxx`。
5. **写状态要原子**：先写 `.tmp` 再 `renameSync` 覆盖目标（Windows 上走 ReplaceExisting）。
6. **Electron 宿主看不到 stdout**，日志同时落 `life.log`；排查问题先看它。
7. **不要在每轮 tick 都写状态文件**。每 30 秒写一次会和「小夜自己在写 log」抢同一个文件，
   改完之后只在真有事件/入账/投递时落盘，能量靠锚点现算。
8. **自然醒要有「起点没满」这个前提**。否则一觉从满格开始（迁移过来的老状态就是这样），
   一上来就会被判成「睡到自然醒」，直接把人叫起来。
9. **旧账本绝对不能重算**。老版本的 `energy` 已经扣完了，升级时必须把所有老记录标成
   已入账，否则一重启就白扣一轮。
10. **睡着的时候不能有行为**。做梦那条消息只许她写 `梦境.md`；如果她趁这一轮写了日记、
    刷了网页、往 log 里记了事，`入账()` 会把这类记录按 0 扣并打上 `睡眠期` 标记——
    账本上不会给「睡着干活」付钱。踩过这个坑：早期文案写的是「记进今天的日记或者 log 都行」，
    结果一条梦变成了一整篇日记。

## 已知限制

- 任务分类（工作/生活/娱乐/跑神）仍然由小夜按 `actions.json` 自己掷，插件不干预。
- 梦的内容必须由模型写，插件只负责「这个整点该做梦了」并把她叫起来。
- 单进程边界：DSH 桌面版进程活着（窗口藏托盘也算）定时器才在跑；退出应用就停。
  因为账本用绝对时间锚点，停多久都不会算错，最长的那段靠下一次 `对齐()` 一次补齐。
- 设置页每 10 秒轮询一次 `/state`，没有做 SSE。
- 迁移后会看到同一觉有两条 `睡觉` 记录：一条是旧版本留下的计划条目（已入账），
  一条是引擎在醒来时补的实际条目。

## 与其它插件的关系

唤醒消息的形状照 `@deepseek-ai/dsh-llm` 的 `createUserMessage` 手搓：`id` 非空、`role: user`、
`content` 是数组、`source.kind = 'dsh-life-cycle'`——会话日志里能一眼看出这条是闹钟响的，
不是主人开口。client 自注册约定沿用 `dsh-feiyu-mood`，定时器 + followup 的写法沿用 `dsh-speak-up`。
